# 考研英语长难句分析工具

**当前版本：v1.5.1** ｜ 单文件、零运行依赖、零构建

一个**单文件、纯前端**的考研英语长难句精析工具。粘贴一段英文文章，它会调用 DeepSeek API 通读断句，逐句划出句子成分与从句层级、标注重难点词汇、给出整句译文；单击任意单词先用**内置的本地词典**即时给出释义，还能让 AI 对任意一句做**逐层语法精析**。

> API Key、缓存、生词本和用量记录保存在当前浏览器。AI 功能由浏览器直连 DeepSeek：调用时会发送 API Key，以及相应的文章、上下文或图片；本地查词与收藏不会发起 AI 请求。

**修复六项问题**

1. 部分成功和全部失败时的进度函数作用域错误，确保恢复按钮并报告准确状态。
2. 单句重试后没有写回所属文章缓存、词汇及打印状态未更新，以及旧请求覆盖新文章。
3. 重复从句文本的区间记录错误；分别定位相同文本并保留合法嵌套。
4. 图片异步处理导致上传顺序漂移，改为稳定 ID 和预留位置。
5. 解词、语法缓存缺少实际提示词与上下文，改为完整发送内容和模型的指纹，并升级缓存版本。
6. AI 断句跨段移动原文，改为逐段验证，校验失败回退本地规则。

### v1.4

**本地词典扩容到 12 万词 + 三条查词兜底规则**

起因是「2 万多个词有点少」。实测下来发现**词量其实不是瓶颈**，所以这次是「扩词表」和「加规则」一起做。

先用全量 ECDICT（77 万词条）把各档的体积与收益测了一遍（难词查得率 = 排除 the/of 这类功能词后，学习者真会去点的那些词的命中率）：

| 词表 | 条数 | index.html | 线上传输 | 难词查得率 |
|---|---|---|---|---|
| v1.3：高频2万+考试标签 | 23,198 | 1.50 MB | ~1.07 MB | 97.0% |
| 高频5万+标签 | 51,070 | 2.69 MB | ~1.98 MB | 97.4% |
| **v1.4：高频12万+标签** | **120,893** | **4.75 MB** | **~3.57 MB** | **98.3%** |
| 全部 40 万 | 400,847 | 12.98 MB | ~9.89 MB | 100% |

关键发现：**所有带考试标签的词本来就已经在词表里了**，所以调大词频档位加进来的几乎全是「不在任何考试大纲里」的词 —— 化学/医药术语、生僻词、人名地名（`methylantipyrine` 甲基安替比林、`colpoptosis` 阴道脱垂、`leifite` 白针柱石、`currey` 英格兰人名）。从 2.3 万扩到 40 万，体积翻 8.6 倍，查得率只从 97.0% 涨到 100%。

所以**同时补了三条零体积的查词兜底规则**，它们把 v1.3 词表的查得率从 97.0% 直接抬到 98.7%：

| 规则 | 例子 |
|---|---|
| **英式拼写 → 美式** | `emphasise` → `emphasize`、`marginalised` → `marginalized`、`colour` → `color`、`analyse` → `analyze` |
| **连字符拆词** | `decision-making` → `decision`、`well-known` → `known` |
| **缩写 / 合并形式** | `cannot` → `can`、`can't` → `can`、`don't` → `do` |

命中兜底规则时，释义卡上会写明「是英式拼写，按美式 emphasize 查的」这类说明，不会让你以为查错了。

**同时修掉一个扩容带来的质量回退**：ECDICT 会给变形词单独生成很薄的「填充条目」，12 万档把它们也收了进来，于是点 `brought` 只得到「bring的过去式和过去分词」、点 `aroused` 只得到「唤醒」，都比原形条目差得多。现在加了一条判据：**直接命中的条目没有考试标签，且（释义是「X的过去式」这类指针，或干脆没有音标）** → 判定为填充条目，改用原形；有音标就说明 ECDICT 拿它当正经词条收了（`camper` 露营者、`better` 较好的、`hearing` 听证会、`marketing` 营销），保留自身。实测 15,965 个有原形可切的变形词里，11,312 个会切到原形。

**性能**：12 万词解压 + 建索引实测约 180 ms（Node；浏览器同量级）。词典仍然不在启动时解压，而是首次点词时懒加载 + 页面空闲时预热，首屏不受影响。

- **带词形还原**：点 `aroused` 会查到 `arouse`，点 `brought` 会查到 `bring`，卡片里会标注「是 … 的变形」
- **不需要 API Key**：本地查词与 AI 无关；没设 Key 也能用
- 词典里没有的词（专名、生僻词）会明确提示「本地词典未收录」并给一个「用 AI 详解」按钮
- 双击单词仍然是 AI 详解，只是弹窗顶部会先显示本地词条
- 「更多」菜单里有 **「单击查词：开/关」**，关掉就恢复成「单击只做高亮」

**修复**
- **词条短语里点非首词，只给词组首词的释义**：有词条的短语（如 `rare bird`）会被合成一个单元，单击时只按整条单元的文本查，查不到就退回首词 `rare` —— 点 `bird` 也只会看到 `rare`。现在按**点击坐标**反查真正被点到的那个词（`caretRangeFromPoint`），再依次退回整条词组、词组首词
- **同一个词组单元里换词会把卡片关掉**：开关判定原本只比 unit 不比词，点完 `bird` 再点 `rare` 卡片直接消失。现在要「同一个词」再点才关
- **AI 弹窗里不再叠一份本地词条**：用户是主动长按/双击要 AI 解析的，词典释义已经在单击的卡片里给过了
- **划线的从句里点不动词**：以前只有「非 `other` 成分」的单元才带 `clickable`，于是从句里被模型标成 `other` 的那些词（`that` / `which` / `and` / `it` 这类）整片点不动 —— 现在能不能点只取决于这块里有没有字母，标点块仍然不可点
- **折叠状态一个词都点不了**：没展开的原句原本是一整段纯文本，没有可点的词单元。现在折叠时也逐词切分（`.p-word`），非词字符原样输出，渲染结果仍与原文逐字一致
- 长按查词原本只监听 `touchstart`，**鼠标用户根本按不出来**；改成 Pointer Events，鼠标与触屏都能用，并且先划选词组再长按会直接解释整条词组
- 释义卡可能跑出屏幕：单词在视口外（还没滚到位）时点，翻转逻辑没有兜底夹取
- 刚打开的释义卡被自己关掉：打开时触发的那次滚动事件会「迟到」送达，被滚动关闭逻辑误伤

### v1.2

**新增：语法精析**
- 展开任意一句，点工具条上的「语法精析」，AI 把句子拆到「主句 — 从句 — 成分 — 汉语意思」三层
- 输出是**渲染好的 Markdown**（标题 / 列表 / 引用 / 表格 / 行内代码），固定四段：句子主干、从句与层级、成分拆解（表格）、翻译与要点
- **每处结构成分后面都用 `()` 附汉语意思**（如 `宾语从句 (他认为这件事很重要)`），括号里的中文会被自动识别并弱化排版
- 结果按「句子 + 提示词指纹」缓存，收起再展开不重复计费；可单独「重新生成」或整块「收起」；打印时自动展开并保留表格边框
- 提示词弹窗升级为**两个 tab**（解词 / 语法精析），语法精析占位符 `{sentence}` `{trans}` `{context}` `{extra}`

**修复：成分被漏标时单词异常变灰**
- 模型偶尔漏标一两个词，空隙被一律补成 `other`；而 `other` 的词**带释义时**会被强行套上灰色，同一词不带释义却正常 —— 看起来像故障
- 现在空隙里含字母数字就沿用上一段的成分类型，`other` 也不再被强行上灰

## 功能

**断句与成分分析**
- 先让 AI 通读全文断句（失败自动回退到内置的本地规则断句，缩写、小数点、省略号都能正确处理；从 PDF 复制来的硬换行文本也会先接回整段再断句）
- 逐句切分语法成分：主语 / 谓语 / 宾语 / 表语 / 定语 / 状语 / 补足语 / 同位语 / 插入语
- 单独识别 **6 类从句**：主语从句 / 宾语从句 / 表语从句 / 定语从句 / 状语从句 / 同位语从句
- **视觉分两层**（成分与从句是两条正交的线，互不干扰）：
  - **黄底 = 主句主干**（主/谓/宾/表）；**彩色字 = 成分**，颜色**越往从句里走越淡**，一眼看出「主句的主干」和「从句里的主干」
  - **线型 = 从句**：主语从句双横线、宾语从句单实线、表语从句虚线、定语从句波浪线、状语从句点线、同位语从句点划线
  - 从句**不再用底色**；层层嵌套时内外线在**文字下方按层级向下并排**，能直接看出嵌套层级（最多 3 层）
  - 为了让线不压字：有从句的句子会自动加大行距，并把**释义气泡移到文字上方**（类似注音），下方整条带子留给从句线
  - 悬停任意成分/从句可看到模型给出的判断依据
- 每句都有中文译文，可整句复制

**词汇**
- 自动抽取考研难度的重难点词汇与固定搭配，右侧栏按原文顺序列出
- 单击词表条目可跳转定位到原文（含 `R&D`、`it's` 这类带符号的词条）
- 图例栏分**两行**（成分 / 从句）共 15 个标签，点击可筛选，只看某一类成分或某一种从句；每个标签都带线型小样与悬停提示

**查词（折叠状态和展开状态都能用）**
- **单击任意单词 → 保留荧光笔涂黄 + 弹出本地词典释义卡**（同一时刻只保留一处高亮）
- **两种状态都是逐词切分**：没展开的原句（图一那种）也会把每个词切成独立可点单元，不展开也能查词；展开后的标注同理，**能不能点只看这块里有没有字母，与成分着色无关**
- **点哪个词就查哪个词**：有词条的短语会合成一个单元（如 `rare bird`），点 `bird` 查的是 `bird`、点 `rare` 查的是 `rare`；只有在都查不到时才退回整条词组、再退回词组首词
- 释义卡显示：音标、中文释义（多义分条）、考试标签、词形变化（过去式/复数…）
- **变形词会自动还原**：点 `aroused` 查到 `arouse`、点 `brought` 查到 `bring`，并标注变形来源（也要避免被词典里那些很薄的「变形填充条目」挡住 —— 见 v1.4 更新日志）
- **三条查词兜底**：英式拼写（`emphasise` → `emphasize`）、连字符拆词（`decision-making` → `decision`）、缩写（`cannot` / `can't` → `can`）。命中时卡片会说明是走哪条规则查到的
- 词典未收录 → 提示「本地词典未收录」+「用 AI 详解」按钮
- **长按 500ms → 直接调 AI**（鼠标按住不放和触屏长按都行）。词典只能查词、查不了词组，所以**想知道词组含义就先划选词组再长按**，AI 会解释整条词组
- **AI 弹窗里只有 AI 的内容**，不会再叠一份本地词条（要查词点一下就好，不需要花额度）
- 双击单词同样调 AI 详解；「更多」菜单里可关闭「单击查词」，改成只高亮

**语法精析（AI 逐层拆解）**
- 展开任意一句，点工具条上的 **「语法精析」**，AI 会把这句话拆到「主句 — 从句 — 成分」三层
- 输出是**渲染好的 Markdown**（标题 / 列表 / 引用 / 表格 / 行内代码都支持），不是一堆纯文本
- **每一处结构成分后面都用 `()` 附上汉语意思**，例如 `宾语从句 (他认为这件事很重要)`、`后置定语 (住在隔壁的)`；这些括号里的中文会被自动识别并做弱化排版，读起来像批注
- 固定四段结构：句子主干 / 从句与层级 / 成分拆解（Markdown 表格，列为 层级·原文片段·成分·汉语意思·说明）/ 翻译与要点
- 结果缓存在本地，**同一句不会重复消耗额度**；句子里可以「重新生成」，也能整块「收起」
- 打印 / 导出 PDF 时自动展开、保留表格边框

**可自定义 AI 提示词（两套）**
- 顶栏齿轮按钮（或解词弹窗里的「编辑提示词」），弹窗里有 **「解词提示词」/「语法精析提示词」两个 tab**
- 解词支持占位符：`{word}` `{sentence}` `{trans}` `{context}` `{extra}` `{schema}`；`{word}` 与 `{schema}` 是必需的
- 语法精析支持占位符：`{sentence}` `{trans}` `{context}` `{extra}`；`{sentence}` 是必需的（输出是 Markdown，所以没有 `{schema}`）
- 实时预览：用示例值把提示词渲染出来，所见即所发
- 改了哪一套提示词，就只让那一套的旧缓存失效（缓存键带提示词指纹）

**缓存**
- 分析结果、解词结果与语法精析结果都缓存在本地，重看同一篇文章不消耗 API 额度
- **超过 7 天没有访问过的缓存自动清除**，最多保留 40 条
- 顶栏垃圾桶按钮可查看占用、手动清理过期缓存或全部清空

**多端适配**
- 桌面 / 平板 / 手机三档断点
- 窄屏顶栏自动收拢为「更多」菜单
- 手机端「核心词汇」折叠为可展开的底部面板
- 触屏去掉了 hover 视觉残留，补上长按交互

**其它**
- 打印 / 导出 PDF（自动展开全部精析，黄底与从句线都会一起打印出来；分析失败的句子保留原文而不是只印一个错误框）
- 支持粘贴文本或上传图片，按页识别、排序与校对后追加／替换正文（替换已有正文需确认）
- 显示偏好记忆：译文显隐、释义显隐、翻译显示模式、标注区字体（衬线/无衬线）
- 键盘可用：句首序号可用 Enter / 空格展开收起，「收起本句」按钮在每句精析底部
- 只成功了一部分也会缓存，重新打开时**只补跑失败的句子**，不会整篇重跑

## 使用方法

1. 打开 `index.html`（双击即可，或访问部署好的在线地址）
2. 点右上角 **设置 API Key**，填入你自己的 DeepSeek API Key
   - 在 [DeepSeek 开放平台](https://platform.deepseek.com/api_keys) 创建
   - Key 只保存在你浏览器的 `localStorage` 里
3. 粘贴考研英语文章（1000 词以内效果最佳，段落之间用空行分隔）
4. 点「开始分析」

> 想先看效果可以点「载入示例」，它内置了一段考研真题风格的短文。

### 独立查词

桌面点顶栏“查词”，手机／平板在“更多”菜单中点“查词”。输入单词或词组，点击“查询”或按回车。内置词典命中后直接显示释义，可收藏到默认生词分类；词形还原及英美拼写等规则沿用原有词典。

本地未收录完整词条时会自动打开 AI 详解，需要已设置 API Key，并按实际 API 用量计费；AI 结果同样可以收藏。查词无需载入文章，AI 解释使用无上下文模式。AI 命中已有本地缓存时不再请求接口。

### 生词本与 Anki

1. **Alt＋左键**点原句中的单词即可收藏；也可在查词卡或 AI 弹窗点“收藏到生词本”。收藏本身不消耗 API 额度。
2. 顶栏点“生词本”（手机在“更多”中），创建一级文件夹，并通过“默认收藏”选择位置。星号表示默认位置。
3. 点击词条的“编辑词条”可修改释义和笔记；勾选词条后可批量移动。不同分类可分别保存同一个单词，同分类按规范化拼写合并，`work` 与 `works` 不强制合并。
4. 可导出当前分类、全部分类或选中词条为 `.txt`。正面是单词，背面包括释义、音标、笔记及全部原句、译文和语境释义；分类对应 `考研生词::分类名` 牌组。分类名中的冒号会转换为全角冒号，避免意外增加牌组层级。
5. 在 **Anki 2.1.54+** 导入文件，选择具有正面／背面两字段的笔记类型（如“基础”），确认 Front → 正面、Back → 背面、Deck → 牌组。导出文件使用 UTF-8 编码，并声明 Tab 分隔、HTML 内容及第 3 列牌组；导入时保留 HTML 设置。
6. **匹配范围选择“笔记类型及牌组”**，这样跨分类同词会分别导入；重复导入选择“更新”即可更新原笔记。文件格式和重复匹配说明见 [Anki 官方手册](https://docs.ankiweb.net/importing/text-files.html)。

生词本不会随缓存过期或“清空缓存”删除。请定期下载 **JSON 备份**；恢复会替换当前生词本，并要求确认。清除浏览器站点数据、使用不同浏览器／网址可能看不到原数据。存储失败时会明确提示，词条不会假装保存成功。

### 取消与预估费用

分析、单句重试或 OCR 运行时出现“取消”按钮。取消后已完成句子会缓存，再次分析只补齐未完成句子；OCR 保留已识别页面与已编辑文字，再次识别跳过已完成页。取消可能无法阻止服务端已经产生的费用。

顶栏“费用统计”（手机在“更多”中）显示最近任务和本地累计。默认费率按 v1.5 约定：每百万 token，命中输入 **¥0.04**、未命中输入 **¥2**、输出 **¥8**；“闲时”预设为一半，也可自定义。费率需要按使用的模型和平台报价自行调整，应用不会自动判断闲时或更新价格；可参考 [DeepSeek 官方价格](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)。修改费率只影响后续请求，历史请求保留当时快照。

金额始终是**估算**，最终以平台账单为准。本地缓存命中不发请求；截断、模型解析失败及重试的回执均计入。网络中断、取消或缺少完整 token 明细的请求标为“未知用量”，已知 token 尽量保留，未知部分不计入已知金额，不能据此认定费用为零。

### OCR 校对

切换“图片”后上传或粘贴图片。等待全部图片处理完成，再用拖动或上下按钮调整顺序并开始识别。每页显示进度和可编辑转录文字；失败页可单独重试，点击缩略图放大原图。桌面左右对照，手机上下排列。

校对后选择“追加正文”或“替换正文”，页面按当前顺序用空行分隔。若有未识别页面，会先确认是否只使用已有文字。图片和草稿不会持久化，刷新／关闭页面前请应用到正文或另行保存。

## 说明与边界

- **需要自备 API Key**，分析会消耗你自己的 DeepSeek 额度。并发 3 批、每批 5 句，可用文件顶部的 `BATCH_SIZE` / `CONCURRENCY` / `MAX_TOKENS` 调整；语法精析是单句一次调用，只有你点了才会发。
- **断句失败或逐段校验不通过会自动降级**为本地规则断句，界面会明确提示「本地规则断句」；主动取消不会继续兜底分析。
- **标注会有误差**。成分与从句划分由模型生成，遇到特别刁钻的句子可能标错；工具会做词边界校正、从句跨度合法化（允许嵌套、禁止部分重叠）与「原文逐字还原」校验，保证**不会丢字或重复**，但语法判断请以教材为准。
- **语法精析的内容同样由模型生成**，结构（四段 + 表格 + 每处成分带汉语意思）由提示词约束，但语法结论请自行判断；不满意可以直接改提示词。
- 如果模型没按新格式返回从句（或返回空），页面会自动降级为「只标成分、不画从句线」，不会白屏。
- 分析失败的单句可以在句内点「重试」，不会整篇重跑；只成功了一部分时，重新分析也只会补跑失败的那几句。
- 输出被 max_tokens 截断时，该批会自动劈成两半重试，不需要手动一句句点重试。
- 浏览器直连 DeepSeek API，若你的网络环境需要代理，请确保浏览器能访问 `api.deepseek.com`。
- **`index.html` 约 5 MB**：主体体积来自内嵌词典数据（base64 后的 gzip）。这是「保住单文件、离线可用」的代价；如果不想要词典，删掉文件末尾 `<!-- ECDICT_DATA_START -->` 到 `<!-- ECDICT_DATA_END -->` 之间的内容即可，页面会照常工作，只是单击查词提示「词典数据缺失」。
- **本地词典需要 `DecompressionStream`**（Chrome 80+ / Edge 80+ / Firefox 113+ / Safari 16.4+）。不支持的老浏览器会自动降级：查词卡片提示原因，AI 功能不受影响。词典是**首次点词时才解压**（并在页面空闲时预热），所以不影响首屏和分析速度。

## 词典数据与许可

本地查词用的是 **ECDICT** 的一个子集，内嵌在 `index.html` 末尾的 `ECDICT_B64` 里（base64(gzip)，运行时用 `DecompressionStream` 解开）。

- **数据来源**：[skywind3000/ECDICT](https://github.com/skywind3000/ECDICT)（Free English to Chinese Dictionary Database）
- **许可**：MIT License，`Copyright (c) 2025 Linwei`。完整声明见 `index.html` 里数据块上方的注释与本 README。原始数据共 77 万词条。
- **裁剪口径**：`frq` 词频前 120,000 ∪ 带任一考试标签（`ky` 考研 / `cet4` / `cet6` / `toefl` / `ielts` / `gre` / `gk`）→ **120,893 条**，gzip 后约 3.4 MB。档位可用 `--freq-top N` 调整，别手改 base64。
- **为什么不能只按「考研标签」裁**：实测那样只有 6,000 词左右，而 `idea / groups / people / speak / name` 这些常用词在 ECDICT 里根本没打考试标签，真实文章里**只有约 60% 的难词查得到**。必须「词频 + 标签」两条腿，才能到 96% 以上。
- **字段**：`word` / 中文释义 / 音标 / 考试标签 / `exchange`（词形变化）。记录间用 `\n`，字段间用 `\x01`。ECDICT 的多义分隔在 CSV 里是**字面的 `\n` 两个字符**，构建时会被换成 `|`，前端再按 `|` 分条渲染。
- **词形还原**在运行时从每条的 `exchange` 正向+反向构建（`d:aroused` 之类给出变形→原形，`0:arouse` 给出原形），12 万条会产出约 40,800 条映射，不额外占体积。
- **查词兜底规则**（英式拼写 / 连字符拆词 / 缩写）是纯代码，零体积；实测这条比继续扩词表划算得多（见 v1.4 更新日志）。

### 重新生成词典

必须用构建脚本，不要手改那串 base64：

```bash
# 1. 拿到 ecdict.csv（约 63 MB）
git clone --depth 1 https://github.com/skywind3000/ECDICT.git /tmp/ECDICT

# 2. 重新裁剪并注入 index.html（会替换两个标记之间的内容）
node tools/build-dict.js /tmp/ECDICT/ecdict.csv --inject index.html

# 想换档位就加 --freq-top（默认 120000）：
node tools/build-dict.js /tmp/ECDICT/ecdict.csv --inject index.html --freq-top 20000

# 只想看统计、不动文件：
node tools/build-dict.js /tmp/ECDICT/ecdict.csv
```

脚本会自己跑自检（条数、重复键、空释义、非法词形、gzip 往返一致），失败会以非 0 退出。

**调档位前先想清楚**：`--freq-top` 调大加进来的几乎全是「不在任何考试大纲里」的词（因为带考试标签的词本来就已经全在里面了），实测从 2 万调到 12 万只把难词查得率从 97.0% 抬到 98.3%，而体积涨了 3 倍。**要提升查得率，优先加兜底规则**（`index.html` 里的 `BRIT_RULES` / `CONTRACT_MAP`，以及 `preferLemmaEntry` 的变形词取舍），那才是零体积的收益。

## 技术实现

- 零运行依赖、零构建，单个 HTML 文件（HTML + CSS + 原生 JS）；测试工具仅用于开发
- **内置词典用 base64(gzip) 内联 + `DecompressionStream` 运行时解压**：既保住了「单文件、双击就能用、离线可用」，又不用把 5.4 MB 明文塞进文件。词典**不在启动时解压**，而是首次点词时懒加载，并在 `load` 后 1.5 秒用 `requestIdleCallback` 预热，所以不拖慢首屏和分析。查词链路完全不碰 API。
- **词形还原表从 `exchange` 正向构建**：变形词（`aroused`、`constitutes`）的 `frq` 往往是空的，根本进不了高频词表，所以只靠「变形词自己的 `0:`」会漏掉绝大多数；必须同时用原形条目上的 `d:/p:/i:/3:/s:/r:/t:` 反推变形。实测这一步把难词查得率从 78% 拉到 96.5%（后经扩容与兜底规则进一步提升）。
- **两层正交的标注模型**：`segments` 负责句子成分（覆盖全文、互不重叠），`clauses` 负责从句跨度（允许嵌套、禁止部分重叠，深度由前端按包含关系算出）。成分决定文字颜色与主句主干底色，从句决定线型与嵌套线位。
- **从句线用 `background-image` 画在包裹层上，而不是 `text-decoration`**：Chrome 不会把文字装饰传播进 `display:inline-flex` 的单词单元（只在词间空格上留碎片），实测波浪线/双线/点线在包裹层方案下完全不显示；渐变/SVG 背景可以跨单词连续、换行每行都有，也能与黄底共存。
- **线的垂直位置靠 `padding-bottom` 控制，前提是 `.unit` 必须 `vertical-align:baseline`**：用 `bottom` 会把包裹层的盒子顶到文字上方（实测盒底比文字底高 14px），那种情况下 `padding-bottom` 加多少线都还压在字上。层级越深，`padding-bottom` 越大，线就排得越靠下。
- 分词 → 成分区间对齐 → 从句跨度合法化 → 逐单元着色，并有「原文逐字还原」的自动化校验
- **语法精析的 Markdown 渲染器是自己写的**（零依赖）：只覆盖用得到的子集（标题/段落/粗斜体/行内代码/代码块/列表/引用/分隔线/表格），安全策略是**先把整段文本 HTML 转义、再套标签**，所以 AI 返回里塞 `<script>` 或 `onerror=` 只会变成可见文字，不可能执行（已用 12 种注入载荷 + 7 个注入位置做自动化验证）。
- 「括号里的汉语释义」用一条只匹配**含中文**的括号的正则处理，`: (他认为这件事很重要)` 会被包成 `.zh` 弱化排版，而英文语境里的 `(Figure 1)` 不受影响。
- 词条定位用「受控词形匹配 + 只在连续词上匹配 + 取最优候选」，不做任意前缀匹配（避免 `form` 命中 `Formerly`、`look after` 跨半句命中）
- 缓存带版本前缀、统一索引、访问时间戳与 TTL；升版本时会对账清理旧版本数据，孤儿键会被收编进索引而不是永远占着配额
